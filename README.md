# NexAura AI Teaching Assistant Demo

A clean, demo-ready **per-school login** web app for NexAura. This demo is built on **Next.js (App Router) + Supabase + OpenAI**, with a minimal curriculum grounding pipeline and internal usage logging.

> **Privacy**: This demo does **not** store generated lesson plans/resources/feedback. Downloading generated content is supported via DOCX.

---

## ✅ Key Features

- **Per-school login only** (one login per school, no teacher accounts, no school selector)
- **Three tabs**: Lesson Planner, Resource Generator, Feedback
- **Curriculum grounding** with citations (Stage 1 keyword retrieval)
- **Backend-only ingestion pipeline** for future curriculum updates (Stage 2 stub)
- **PII warnings** + confirmation modal for emails/phone numbers
- **Internal usage logging** + **protected CSV export endpoint**
- **Download as DOCX** for all outputs

## 2) Supabase Setup (Click-by-Click)

### A) Create project

1. Go to [https://supabase.com](https://supabase.com) and sign in.
2. Click **New project**.
3. Set **Project name** (e.g. `nexaura-demo`).
4. Set **Database password** (save this).
5. Click **Create new project**.

### B) Run database migration

1. Open your project in Supabase.
2. In the left sidebar, click **SQL Editor**.
3. Click **New Query**.
4. Paste the entire contents of `supabase/migrations/001_init.sql`.
5. Click **Run**.

### C) Configure Auth settings (required for demo signup)

1. Left sidebar → **Authentication** → **Providers**.
2. Ensure **Email** is enabled.
3. **Disable email confirmations** for demo speed:
   - Authentication → **Settings** → **Email Auth**
   - Turn **Confirm email** OFF

> If you keep email confirmation on, the signup flow will not create sessions and school creation will fail.

### D) Get Supabase keys

1. Left sidebar → **Project Settings** → **API**.
2. Copy:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` key → `SUPABASE_SERVICE_ROLE_KEY` (server-only)

## 3) OpenAI Setup

1. Create an API key at [https://platform.openai.com/api-keys](https://platform.openai.com/api-keys)
2. Add to `.env.local`:
   ```
   OPENAI_API_KEY=your_key
   MODEL_NAME=gpt-4o-mini
   ```

---

## 4) Vercel Deployment (Click-by-Click)

### A) Connect GitHub repo to Vercel

1. Go to [https://vercel.com/new](https://vercel.com/new)
2. Click **Import Git Repository**
3. Select this GitHub repo

### B) Configure environment variables

1. Vercel project dashboard → **Settings** → **Environment Variables**
2. Add all values from `.env.example`:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `OPENAI_API_KEY`
   - `ADMIN_EXPORT_TOKEN`
   - `DISABLE_SIGNUP` (set `true` to disable self-serve signup)
   - `MODEL_NAME`

### C) Deploy

1. Go to **Deployments** → **Deploy**
2. Wait for build to finish
3. Click the generated URL to verify

## 5) Curriculum Grounding

### Stage 1 (implemented now)

- Curriculum placeholders live in `data/curriculum/placeholder.md`
- Keyword-based retrieval pulls top matches into the prompt
- Citations are returned as `Placeholder Curriculum v0.1` (file name)

### Stage 2 (backend-only, no UI)

**Upload location**:
```
data/curriculum/uploads/
```

**Ingestion stub**:
```
node scripts/ingest-curriculum.ts
```

This will:
- scan `uploads/`
- read `.md` / `.txt` files
- skip PDFs for now (stubbed)
- write `data/curriculum/index.json`

**NexAura staff update flow:**

1. Drop curriculum files into `data/curriculum/uploads/`
2. Run:
   ```bash
   node scripts/ingest-curriculum.ts
   ```
3. Commit the updated `index.json`
4. Redeploy to Vercel

## 6) Usage Logging (Internal Only)

Each successful `/api/generate` call logs an event:

| Field | Notes |
|------|------|
| school_id | from `profiles` |
| mode | lesson/resource/feedback |
| latency_ms | request duration |
| model | OpenAI model |
| tokens_estimate | from OpenAI response |
| cost_estimate_usd | optional |

### Export CSV (protected)

```
GET /api/usage-export?days=30
Headers:
  x-admin-token: <ADMIN_EXPORT_TOKEN>
```

Returns a CSV of the last 30 days (max 365).

## 7) Common Errors + Fixes

### ✅ "Invalid redirect URL" in Supabase
- Supabase → Auth → URL Configuration
- Add:
  - `http://localhost:3000`
  - `https://your-vercel-domain.vercel.app`

### ✅ Signup fails with "No session created"
- Disable email confirmations:
  - Auth → Settings → Email Auth → Confirm email = OFF

### ✅ 401/403 auth errors
- Check Supabase keys in `.env.local` / Vercel env vars
- Ensure RLS policies applied via migration

### ✅ Middleware blocking routes
- Ensure `/login` and `/signup` remain public
- `/api/usage-export` uses admin token instead

### ✅ Vercel build fails
- Recheck environment variables
- Ensure `OPENAI_API_KEY` and Supabase vars are set
- Re-deploy
